# Vix 导入与模块解析规则

本文描述**当前实现**。历史上这里写过一套包名展开 + `$VIX_HOME` + `.vix/libs`
的搜索顺序，那套东西从未实现过，已删除。

---

## 一、两种包含形式

| 写法 | 机制 | 命名空间 |
|------|------|----------|
| `import "路径"` | 预处理器**文本包含** | 扁平，并入当前编译单元 |
| `mod "路径.vix"` | 模块图 + AST 合并 | 具名模块，符号加前缀 |
| `mod 名字` | 模块图查找 | 同上 |

`import "路径"` 把目标文件处理后的源码直接拼进当前文件，因此共享同一个符号
空间。`mod` 则构建模块图，合并时给函数和全局变量加 `模块::` 前缀。

`import module::symbol` **不是有效语法**，解析阶段报错。跨模块访问一律使用
限定名：

```vix
mod math

fn main(): i32
{
    return math::add(3, 4)
}
```

---

## 二、带引号路径的解析

解析规则只有一条：

1. 取**导入文件所在目录**（最后一个 `/` 之前的部分）
2. 拼上导入路径
3. 做词法规范化

若导入文件本身不含 `/`（例如从当前目录直接调用），则路径按原样使用。

**没有**搜索路径、没有包名展开、没有环境变量。

### 示例

文件 `src/infer/solver.vix` 中：

| 写法 | 解析结果 |
|------|----------|
| `import "ty.vix"` | `src/infer/ty.vix` |
| `import "../ast.vix"` | `src/ast.vix` |

---

## 三、路径规范化

路径在**读取之前**和**去重比较之前**都会被规范化，因此同一文件的多种拼写只会
被包含一次：

| 拼写 | 规范化 |
|------|--------|
| `./a.vix` | `a.vix` |
| `a//b.vix` | `a/b.vix` |
| `sub/../a.vix` | `a.vix` |
| `../lib/../a.vix` | `../a.vix` |

规范化是**纯词法的**，不要求路径存在——这正是它能作为导入身份使用的原因。
不加规范化时，同一声明会被包含两次，报 `E2006 duplicate struct`。

回归测试：`tests/path_normalize/`。

---

## 四、`mod` 的解析

`mod 名字` 在导入文件所在目录下按顺序查找：

1. `名字.vix`
2. `名字/mod.vix`

两者都存在时报 `AMBIGUOUS`。

`mod "路径.vix"` 直接使用该路径（带 `/` 或 `.vix` 后缀时不做 `名字/mod.vix`
回退）。

---

## 五、内部处理流程

1. 预处理器扫描源码，遇到 `import "路径"` 就定位、规范化、读取目标文件
2. 已在导入集合中则跳过（按规范化后的路径判重）
3. 递归处理目标文件的子导入
4. 把处理后的文本替换掉 `import` 那一行，插入行号填充以保持诊断位置正确
5. `mod` 由模块图处理：token 级扫描 → 建模块树 → 合并 AST → 加符号前缀

---

## 六、当前限制

- `pub` 尚未真正强制：合并时不做可见性过滤。
- 结构体与 ADT 在合并时**不加**命名空间前缀，两个模块定义同名结构体会冲突。
- 同名 ADT 会被静默去重（保留先出现的那个）。
- 这些限制在模块系统重做时一并处理。
